# Dynamic conditioning

In dynamic conditioning every block is integrated in **one** ODE solve: a block's velocity
sees its parents' states at the same time `t`, not their final values (as in static
conditioning). The network is a single masked, block-triangular MLP
(`net.ParallelStructuredFn`, built from `layers.py`), trained with `create_dynamic_flow`.
Training needs the per-block (Knothe–Rosenblatt) noise–data coupling,
`use_coupling='c2ot'`, for the learned conditionals to be consistent; see the paper's
appendix "Noise–Data Coupling".

A trained network can answer a conditional query `p(targets | conditions)` in more than one
way. The difference is how the conditions' trajectories are produced.

| implementation | how conditions enter | used by |
| :--- | :--- | :--- |
| `DynamicDistribution` (`dist.py`, `flow.py`, `subset_velocity.py`) | Each condition is integrated **backward** from its observed value, giving its trajectory on the time grid. The targets are then integrated forward with the conditions read off that trajectory (linear interpolation), and blocks the query does not need are cut out of the network by slicing its weight matrices (`clip_tail`). Conditions are reproduced exactly at `t = 1`, and only the needed blocks are integrated. | `mode="dynamic"` (the paper's results) |
| `ParallelBlockTriangularDistribution` (`parallel_dist.py`) | Each condition is integrated backward **to noise**; the whole system is then integrated forward from that noise together with fresh noise for the targets. Conditions are regenerated by the forward solve, so they match the observed values only up to solver error, and the full state vector is integrated (blocks outside the query held at zero). | the numerical and claim tests (`tests/`), as a simpler reference |

Both use the same trained network and `parallel_flow.ParallelFlow` integrator, so either can
be built from a model trained with `create_dynamic_flow` (`create_dynamic_distribution`,
`create_parallel_distribution` in `dist_factory.py`).
